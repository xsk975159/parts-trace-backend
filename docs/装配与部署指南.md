# 组装与部署指南（开发完成后如何拼起来跑）

本文说明如何在本地或服务器上 **组装**「MySQL + 后端 +（可选）IPFS +（可选）长安链」并切换存储模式。默认无需区块链即可启动。

---

## 1. 组件一览

| 组件 | 是否必须 | 说明 |
|------|----------|------|
| JDK 8+ | 是 | 与 `pom.xml` 中 `java.version` 一致 |
| Maven 3.6+ | 是 | `mvn package` |
| MySQL 8 | 是 | 数据库名默认 `parts_trace` |
| `parts-trace-backend` | 是 | Spring Boot 服务，默认端口 `8080` |
| `parts-trace-frontend` | 否 | Vue 3，构建后静态资源或 `npm run dev` |
| Kubo (go-ipfs) | 否 | 仅当 `PARTS_TRACE_OBJECT_MODE=ipfs` |
| 长安链节点 + SDK 配置 | 否 | `PARTS_TRACE_CHAIN_MODE=chainmaker`；真实上链还需 `CHAINMAKER_SDK_INVOKE_ENABLED=true` 与已部署合约 |

---

## 2. 数据库初始化

1. 创建库：`CREATE DATABASE parts_trace CHARACTER SET utf8mb4;`
2. 执行初始化脚本：`src/main/resources/db/init.sql`

3. 修改 `application.yml` 或使用环境变量覆盖：

```text
KEWEI_DBSERVER=localhost
KEWEI_DBPORT=3306
KEWEI_DBUSER=root
KEWEI_DBPWD=你的密码
```

---

## 3. 后端配置优先级

Spring Boot 读取顺序：`application.yml` < 环境变量 < `application-{profile}.yml`。

### 3.1 仅本地演示（推荐先试通）

无需 IPFS、无需链：

```text
PARTS_TRACE_CHAIN_MODE=db
PARTS_TRACE_OBJECT_MODE=db
```

直接 `mvn spring-boot:run` 或运行打包后的 `java -jar`。

### 3.2 启用真实 IPFS（对象存储）

1. 安装并启动 Kubo，默认 API `127.0.0.1:5001`。
2. 设置：

```text
IPFS_HOST=127.0.0.1
IPFS_PORT=5001
PARTS_TRACE_OBJECT_MODE=ipfs
```

3. `gateway` 仅用于浏览器访问资源，可与 API 同机不同端口（见 `application.yml` 中 `ipfs.gateway`）。

若 IPFS 不可用，后端在写入对象时会报错，请检查防火墙与 Kubo 是否 `ipfs daemon`。

### 3.3 启用长安链模式（锚点存证）

1. 按长安链官方文档准备 **4 节点或 dev 单链**，将 `contracts/trace_anchor/` 编译为 **WASM** 并 **创建/升级合约**（步骤概要见 [../contracts/合约说明.md](../contracts/合约说明.md)）。
2. 复制 SDK 配置：

```bash
cd parts-trace-backend/src/main/resources/chainmaker
copy sdk_config.yml.example sdk_config.yml   # Windows
# cp sdk_config.yml.example sdk_config.yml   # Linux/macOS
```

编辑 `sdk_config.yml`：填入本组织证书、节点 RPC 地址、链 ID 等（**不要将含私钥的文件提交 Git**）。

3. 基础链模式（镜像写库、不强制发交易）：

```text
CHAINMAKER_CHAIN_ID=chain1
CHAINMAKER_ORG_ID=你的组织ID
PARTS_TRACE_CHAIN_MODE=chainmaker
CHAINMAKER_SDK_INVOKE_ENABLED=false
```

4. **真实 invoke**（需节点可达且合约已部署）：

```text
PARTS_TRACE_CHAIN_MODE=chainmaker
CHAINMAKER_SDK_INVOKE_ENABLED=true
```

此时 `ChainMakerSdkInvoker` 会初始化 `ChainClient`，`ChainMakerChainStorageAdapter` 调用 `save_anchor` / `append_vc`；失败或超时将按实现打日志并可能回退镜像（参见源码）。

可选环境变量：

```text
CHAINMAKER_ANCHOR_CONTRACT=
CHAINMAKER_WASM_CONTRACT=trace_anchor
CHAINMAKER_INVOKE_TIMEOUT_MS=60000
```

## 4. 构建与启动

### 4.1 后端

```bash
cd parts-trace-backend
mvn -q -DskipTests package
java -jar target/parts-trace-backend-1.0-SNAPSHOT.jar
```

### 4.2 健康检查

- `GET http://localhost:8080/actuator/health`
- API 文档：`http://localhost:8080/swagger-ui.html`（路径以 `application.yml` 为准）

### 4.3 前端（若使用）

```bash
cd parts-trace-frontend
npm install
npm run dev
```

将前端环境变量中的 `VITE_API_BASE_URL`（或项目等价变量）指向后端 `http://localhost:8080`。

---

## 5. 模式切换检查清单

切换到 **chainmaker + ipfs** 前建议逐项确认：

- [ ] MySQL 可连，`init.sql` 已执行
- [ ] `sdk_config.yml` 存在且节点可达
- [ ] 锚点合约已部署，`wasm-contract-name` 与链上合约名一致
- [ ] 若需真实上链：`CHAINMAKER_SDK_INVOKE_ENABLED=true` 且证书/权限正确
- [ ] Kubo `daemon` 运行中，`/api/v0/add` 可访问（若启用 ipfs）
- [ ] 环境变量或 `application-*.yml` 中 `PARTS_TRACE_*` 已设置
- [ ] 防火墙放行链节点 gRPC、IPFS 5001（若远程）

## 6. 跨链（5.2）组装说明

当前仓库 **未包含** 常驻跨链网关进程与第二套链的默认配置。论文 5.2 落地后，建议单独增加：

- 网关服务配置（监听地址、各链证书、路由表）
- 主链 / 从链两套 `sdk_config` 或通过 profile 区分
- 运维文档：网关与后端启动顺序、重试与死信队列策略

Java 侧已提供 `CrossChainRelayService`（主链 `receive_cross_anchor`），可被中继服务注入调用。

## 7. 常见问题

**Q：启动报找不到 `sdk_config.yml`？**  
A：仅在使用链模式且 `invoke-enabled=true` 时需要有效文件；`db` 模式开发可忽略。若占位文件在 `classpath:chainmaker/sdk_config.yml`，需保证格式合法。

**Q：IPFS 写入失败？**  
A：检查 `IPFS_HOST`/`IPFS_PORT`；本机可 `curl -X POST "http://127.0.0.1:5001/api/v0/version"`。

**Q：`blockchain_record` 里 txId 像 UUID？**  
A：`db` 模式或 SDK 未启用时可能为模拟或镜像交易号；真链联调成功后应为链上真实 txId。
