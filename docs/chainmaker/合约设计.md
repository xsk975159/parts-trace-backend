# 智能合约与链上锚点（精简版）

## 可部署源码（Go → WASM）

本仓库已在 **`contracts/trace_anchor/`** 提供长安链 **Go 智能合约源码**（方法：`save_anchor`、`append_vc`、`revoke_vc`、`receive_cross_anchor`）。  
编译为 WASM、创建合约及 `invoke` 的步骤见：**[../../contracts/合约说明.md](../../contracts/合约说明.md)**。

业务侧哈希上链入口：`ChainStorageAdapter.storeAnchor(ChainAnchorRequest)` → `ChainMakerChainStorageAdapter` →（可选）`ChainMakerSdkInvoker.invokeSaveAnchor`。  
VC 增量上链：`appendVcIfSupported` → `invokeAppendVc`。

## 1. 与论文 5.1 对齐的最小能力

| 能力 | 链上职责（本合约） |
|------|---------------------|
| 锚定 | `save_anchor`：`business_type`、`business_id`、`data_hash`，可选 `object_cid`、`parts_did` |
| DID ↔ VC | `append_vc`：`parts_did` + `vc_id` + `vc_hash`（状态存于 key-field） |
| 撤销 | `revoke_vc`：对应 `vc_id` 写入标记 `0` |

## 2. 与论文 5.2（跨链原型）

| 能力 | 链上职责 |
|------|-----------|
| 主链接收从链摘要 | `receive_cross_anchor`：`source_chain_id`、`source_tx_hash`、`parts_did`、`data_hash`，可选 `object_cid` |

Java 侧封装：`CrossChainRelayService.invokeReceiveCrossAnchor`（需 SDK 与合约已就绪）。

## 3. 配置与调试

1. `application.yml`：`chainmaker.wasm-contract-name` 与部署时合约名一致；`chainmaker.anchor-contract` 可用于存创建后的合约地址（若你方用地址调用）。
2. `chainmaker.sdk.invoke-enabled`：本地无链时保持 `false`；联调真链时设为 `true`。
3. `sdk_config.yml`：从 `sdk_config.yml.example` 复制并按节点填写。
4. 节点与 **contract-sdk-go** 大版本需匹配，详见 `contracts/trace_anchor/go.mod`。
