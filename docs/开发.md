核心开发准则：按批次组织工作，按单件沉淀可信数据；工作人员操作层仅面向批次，系统后台自动完成单件 DID / 事件 / VC 的生成与绑定，兼顾业务操作效率与单件溯源精度，所有交互流程贴合一线工作人员原有作业习惯，无额外学习成本。核心关联规则：DID 与单个零部件（partsId）一对一硬绑定，为单件唯一数字身份；批次（batchNumber）聚合多个单件形成作业单元；同批次同环节的 VC 为 “批次信息一致、单件标识唯一” 的批量同款 VC，所有事件、VC 最终挂接至对应单件 DID 下。开发范围：聚焦溯源模块的功能实现与前端交互流程，无需涉及底层架构设计，需与现有零部件台账、用户权限系统无缝对接，支持批量操作、单件精细处理，所有操作在批次工作台闭环完成，无跨页面频繁切换。
一、核心功能：批次管理模块
1. 批次基础操作功能
支持批次新增：填写批次号（业务唯一）、产品型号、生产数量、计划完成时间、原材料信息、归属生产商等基础信息，提交后系统自动生成对应数量的单件 partsId，且一键触发单件 DID 批量生成，DID 生成规则为 “生产商 DID+batchNumber+partsId + 时间戳”，生成后完成 partsId 与 DID 的一对一硬绑定，生成结果在页面实时展示（生成中 / 成功 X 件 / 失败 X 件）。
支持批次查询与筛选：按批次号、产品型号、生产状态（待生产 / 待质检 / 待物流 / 已完成溯源）、创建时间、生产商等条件筛选，列表展示批次基础信息 + 整体溯源进度（如 “300/300 件完成全流程”）+ 操作人，支持批次详情入口跳转。
支持批次基础信息编辑：仅允许修改计划完成时间、备注等非核心信息，批次号、生产数量等核心信息不可修改，修改后同步至批次下所有单件的关联信息。
2. 批次物理标识管理功能
支持批次下单件二维码 / RFID 批量生成：二维码 / RFID 内容包含 “单件 DID+partsId+batchNumber”，生成后支持批量下载、打印，页面提供 “打印完成 / 物理绑定完成” 状态标记，标记后单件状态更新为 “DID 已激活，可进行溯源操作”，未绑定的单件无法录入后续事件。
支持物理标识补打：针对丢失 / 损坏的标识，可按 partsId/DID 单独补打对应单件的二维码 / RFID，补打后与原 DID/partsId 保持绑定，不生成新标识。
二、核心功能：批次溯源工作台（核心操作页面，所有流程闭环）
1. 工作台页面布局要求
整体为单页面无跳转设计，分为三个核心区域：「批次信息区」（展示批次基础信息、整体状态、操作日志）、「单件状态矩阵区」（核心）、「批量操作区」（提供全流程批量操作按钮）；
单件状态矩阵区以列表形式展示批次下所有单件，固定列头：partsId、DID（可隐藏，默认不展示）、物理标识码、当前流程状态、操作人、操作时间，支持按流程状态筛选（如 “筛选待质检单件”）、按 partsId/DID 模糊查询，异常单件（操作失败 / 质检不合格）标红展示。
2. 生产事件记录功能（生产商角色操作）
交互流程
生产商在批次溯源工作台，确认单件状态为 “DID 已激活”，点击批量操作区「记录生产事件」按钮；
弹出批次级生产信息填写弹窗，仅需填写批次统一信息：生产车间、生产完成时间、操作人、原材料批次、生产工艺备注，支持上传批次生产证明附件（如生产计划表、工艺单）；
提交后页面显示 “生产事件批量存证中（X/X）”，系统后台自动为每个单件生成专属生产事件，计算事件哈希（含附件哈希），完成链上存证，同时将完整事件信息 + 附件存储至 IPFS；
存证完成后，页面单件状态矩阵区中所有单件状态自动更新为 “生产事件已记录”，点击单件可查看单件生产事件详情（含事件 ID、上链交易哈希、IPFS CID）。
异常处理
若批量存证中部分单件失败，页面显示 “成功 X 件，失败 X 件”，失败单件标红，提供「重新批量处理」和「单独处理」按钮，重新处理无需再次填写信息，单独处理可针对失败单件补录信息后提交。
3. 质检事件记录 + 质检 VC 签发功能（质检员角色操作）
交互流程（批量为主，单件精细处理为辅）
质检员在批次溯源工作台，筛选状态为 “生产事件已记录” 的单件，点击批量操作区「记录质检事件 + 签发质检 VC」按钮；
弹出批次级质检信息填写弹窗，填写批次统一信息：质检标准、检测设备、质检结果（合格 / 不合格）、质检时间、操作人，支持上传批次质检报告附件，若质检结果为不合格，需填写不合格原因；
提交后页面显示 “质检事件存证 + VC 签发中（X/X）”，系统后台自动完成：
为每个单件生成专属质检事件，链上存证（事件 ID / 单件 DID / 批次号 / 质检哈希等），完整信息 + 附件存 IPFS；
为每个单件批量签发专属质检 VC，VC 中批次级信息（质检标准、设备、结果）与填写内容一致，单件唯一信息（持有方 DID/partsId、VC ID）由系统自动生成，签发方为质检机构 DID，完成 VC 签名后链上存证，完整 VC 存 IPFS；
操作完成后，页面单件状态自动更新：合格单件为 “质检 VC 已签发”，不合格单件为 “质检不合格，溯源终止”，不合格单件自动冻结 DID，无法进行后续物流操作；
支持单件精细处理：针对批量质检中需单独标记的单件（如个别不合格），在单件状态矩阵区点击该单件「操作」→「单独质检」，弹窗填写该单件专属质检信息，完成后单独更新状态并签发 VC。
VC 核心属性
同批次合格单件的质检 VC：批次业务信息完全一致，单件 DID/VC ID / 上链哈希唯一，一对一绑定对应单件 DID。
4. 物流事件记录 + 物流 VC 签发功能（物流商角色操作）
交互流程（与质检环节逻辑一致，贴合物流作业习惯）
物流商在批次溯源工作台，筛选状态为 “质检 VC 已签发” 的单件，点击批量操作区「记录物流事件 + 签发物流 VC」按钮；
弹出批次级物流信息填写弹窗，填写批次统一信息：物流商名称、发货时间、目的地、运输方式、操作人，支持上传批次物流单附件；
提交后页面显示 “物流事件存证 + VC 签发中（X/X）”，系统后台自动为每个单件生成专属物流事件并链上存证，同时批量签发专属物流 VC（批次信息一致，单件标识唯一），完成链上存证与 IPFS 存储；
操作完成后，页面单件状态自动更新为 “物流 VC 已签发，溯源完成”，该单件全流程溯源数据（生产 / 质检 / 物流事件 + 对应 VC）全部挂接至自身 DID 下。
额外功能
支持物流节点补充记录：如运输途中的中转、到货等节点，可按批次填写中转 / 到货信息，系统自动为每个单件生成对应节点的物流子事件，无需重复签发 VC，子事件挂接至原有物流事件下。
5. 批次内单件精细操作功能
针对批次内的异常单件（操作失败、单独质检 / 物流），在单件状态矩阵区为每个单件提供「操作」下拉菜单，包含：查看事件详情、查看 VC 详情、单独处理（补录事件 / 重签 VC）、冻结 / 解冻 DID（管理员权限）、查看溯源链条；
所有单件精细操作均通过弹窗完成，不跳转页面，操作完成后实时更新单件状态，操作日志同步至批次信息区。
三、核心功能：溯源校验与查询模块
1. 批次溯源进度监控功能
在批次溯源工作台的「批次信息区」，实时展示批次整体溯源进度，按流程拆分展示（生产事件完成率 / 质检 VC 签发率 / 物流 VC 签发率），以百分比 + 数字形式呈现（如 “质检 VC 签发率：280/300，93.3%”）；
展示批次全流程操作日志，包含操作类型、操作人、操作时间、操作结果，支持日志筛选与导出。
2. 单件溯源链条校验功能
支持批次内批量校验和单件单独校验：批量校验可勾选批次内任意单件，点击「批量校验溯源链条」，系统自动根据单件 DID 聚合全流程事件 + VC，完成四重校验（事件哈希验证 / VC 签名验证 / VC 归属验证 / 链条完整性验证），校验完成后展示 “校验通过 X 件 / 失败 X 件”，失败件标注问题节点；
单件单独校验：在单件操作菜单点击「校验溯源链条」，弹窗以时间轴形式展示该单件的全流程溯源链条（生产→质检→物流），每个节点展示事件信息 + VC 预览，校验结果实时展示，失败时明确标注问题原因（如 “质检 VC 签名无效”/“物流事件哈希不匹配”）。
3. 多维度溯源查询功能
1) 批次溯源查询（操作员 / 管理员 / 监管方）
入口：批次管理列表→点击批次号进入详情工作台，直接查看该批次下所有单件的溯源状态、操作记录，支持批次溯源报告批量导出（PDF/Excel），报告包含批次基础信息、溯源进度、单件状态统计、批量操作日志、链上存证汇总信息。
2) 单件溯源查询（全角色 + 终端验证方）
多入口支持：①批次工作台单件操作菜单→「查看溯源详情」；②系统独立溯源查询入口，支持扫码查询（单件二维码 / RFID）、输入 DID/partsId/ 物理标识码查询；
查询结果展示：以时间轴形式展示单件全生命周期溯源信息，每个流程节点包含事件详情、VC 完整信息（含签发方、签名、上链信息）、附件查看入口，支持单件溯源报告导出（PDF），报告包含单件所有溯源数据 + 校验结果，与单件 DID 绑定。
3) 终端极简验证（下游采购商 / 终端用户，仅验证真伪）
入口：系统独立的「溯源验证入口」，仅提供扫码 / 输入 DID 功能，无任何操作按钮；
验证结果：极简展示 “正品（溯源信息完整）” 或 “溯源信息异常（疑似假冒）”，仅展示简版溯源时间轴（无详细业务信息、无附件），兼顾验证效率与数据隐私。
四、核心功能：VC 管理模块
1. VC 批量管理功能
在批次溯源工作台，支持按批次 / 流程环节（生产 / 质检 / 物流）批量查看 VC，点击「批量查看 XX VC」，弹窗展示该批次下所有单件的 VC 列表，包含 VC ID、对应单件 partsId、签发时间、VC 状态、验证结果，支持 VC 详情查看与批量导出。
2. VC 单独查看与验证功能
单件的每个 VC 均提供单独查看入口（事件详情页 / 溯源链条时间轴 / VC 列表），查看页面展示 VC 完整信息（含 W3C 标准字段、签发方签名、链上存证信息），提供「一键验证」按钮，点击后实时完成 VC 签名、归属、完整性验证，展示验证结果。
3. VC 状态管理功能
支持 VC 撤销（签发方权限）：针对已签发但未完成后续流程的 VC，可按单件 / 批次批量撤销，撤销后链上更新 VC 状态为 “已撤销”，单件状态回滚至对应事件记录状态，支持撤销原因填写，撤销日志链上存证；
系统自动更新 VC 状态：VC 过期后自动标记为 “已过期”，不合格单件的 VC 自动标记为 “无效”，均不影响已上链数据，仅做状态标识。
五、前端交互核心要求
1. 操作闭环要求
所有溯源操作（事件记录、VC 签发、链条校验、报告导出）均在批次溯源工作台完成，全程无跨页面跳转，所有精细操作通过弹窗 / 下拉菜单实现，保证用户操作心智统一。
2. 批量操作优先
所有流程环节均以批量操作为主，单件精细处理为辅，批量操作按钮置于工作台显眼位置，单件操作仅作为异常处理补充，符合一线工作人员 “按批次作业” 的习惯。
3. 状态实时联动
单件状态随操作结果实时自动更新，批次整体进度随单件状态实时聚合更新，无需手动刷新，操作结果（成功 / 失败）以弹窗 + 页面红点双重提醒，失败信息明确具体原因，方便快速处理。
4. DID 隐形化处理
前端默认不展示 DID，仅在二维码 / RFID、单件详情、溯源查询结果中展示，工作人员日常操作无需关注 DID，系统后台自动完成 DID 的所有关联与流转，降低操作门槛。
5. 操作简化要求
所有填写弹窗均仅展示批次级统一填写项，无单件相关填写内容，减少工作人员输入量；支持常用信息自动填充（如操作人、当前时间、生产商 / 质检机构 DID），支持附件批量上传，无需单件单独上传。
6. 可视化展示
溯源链条以时间轴形式展示，每个流程节点用不同颜色区分（生产 - 蓝色 / 质检 - 绿色 / 物流 - 橙色），异常节点用红色标注，直观清晰；
批次溯源进度以进度条 + 百分比形式展示，支持鼠标悬浮查看详细数据，方便快速掌握批次作业情况。
