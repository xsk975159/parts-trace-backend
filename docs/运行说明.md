# 后端运行说明

本文对应当前源码。除明确标注外，命令在`parts-trace-backend/`目录执行，文件路径也相对于该目录。环境部署见[部署说明](部署说明.md)，接口和数据关系见[功能与数据说明](功能与数据说明.md)。

## 1. 环境与配置

后端使用Java 8或Java 11、Maven和MySQL 8。项目以Java 8为编译目标；使用较新JDK时，Maven同时限制只能引用Java 8标准库API。依赖版本以[pom.xml](../pom.xml)为准。

| 环境变量 | 作用与默认值 |
| --- | --- |
| `KEWEI_DBSERVER` | 数据库主机；应用默认`localhost`，本地脚本默认`127.0.0.1` |
| `KEWEI_DBPORT` | 数据库端口，默认`3306` |
| `KEWEI_DBUSER` | 数据库账户，默认`root`；按实际部署替换 |
| `KEWEI_DBPWD` | 数据库密码，应用默认空值；本地脚本在未设置时提示输入 |
| `JWT_SECRET` | 至少32字符的独立随机密钥，用于签发和验证登录令牌 |
| `KEY_ENCRYPTION_KEY` | 32字节密钥的Base64编码，用于AES-256-GCM加密托管私钥 |
| `PARTS_TRACE_CHAIN_MODE` | 默认`db`；真实SDK模式为`real`，兼容旧值`chainmaker` |
| `PARTS_TRACE_OBJECT_MODE` | 默认`db`；实际IPFS模式为`ipfs` |
| `SERVER_PORT` | 后端监听端口，默认`8080`；修改后同步调整前端开发代理 |

配置来源为[application.yml](../src/main/resources/application.yml)。不要把数据库账户密码或实际部署私钥写入版本库。

## 2. 数据库准备

### 新建数据库

仅对新库或已明确决定重建的库执行[init.sql](../src/main/resources/db/init.sql)。该脚本包含删除旧表的语句，不能用于升级已有业务库。

在后端目录打开MySQL客户端，主机、端口及账户按实际环境填写：

```powershell
mysql -h 127.0.0.1 -P 3306 -u root -p --default-character-set=utf8mb4
```

进入`mysql>`后执行：

```sql
SOURCE src/main/resources/db/init.sql;
SOURCE scripts/check-schema.sql;
```

初始化脚本创建并选择`parts_trace`，包含当前业务表、跨链任务表及可选的多机构确认表。执行完成且无缺项后退出客户端。源码启动和普通Windows运行包不自动执行这些SQL；Windows独立版由自己的启动器初始化私有数据库。

### 升级已有数据库

先停止后端并备份`parts_trace`。以下命令中的`root`、主机和端口都是本地示例，应与实际连接配置一致。命令要求MySQL客户端已加入`PATH`。

```powershell
New-Item -ItemType Directory -Force .local/backups | Out-Null
mysqldump -h 127.0.0.1 -P 3306 -u root -p --single-transaction --routines --triggers --result-file=.local/backups/parts_trace-before-upgrade.sql parts_trace
mysql -h 127.0.0.1 -P 3306 -u root -p --default-character-set=utf8mb4 parts_trace
```

在`mysql>`中依次执行：

```sql
SOURCE src/main/resources/db/cross_chain_migration.sql;
SOURCE src/main/resources/db/V20261025__security_completion.sql;
SOURCE scripts/check-schema.sql;
```

前两个脚本补齐跨链基础表、字段、任务表、审计表、注销令牌表和唯一索引。最后一个脚本只读检查缺项；检查不返回缺项后执行`quit;`退出。任何升级语句报错都应先处理，再重新检查。

已有库需要启用多机构核验时，在上述升级完成后另执行`SOURCE src/main/resources/db/V20261026__relay_confirmation.sql;`。基础结构检查不包含这个可选表，启用核验功能时由程序单独检查。详细前提见[多机构核验说明](多机构核验说明.md)。

升级不会自动合并重复业务记录。历史凭证编号、事件提交编号或源链交易重复时，需要核对记录后再建立唯一索引。旧模拟交易会标记为模拟，旧SQL形式异常规则会停用。

## 3. 编译与启动

```powershell
mvn package
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-local.ps1
```

默认端口为`8080`。在启动终端按`Ctrl+C`停止。只检查配置、不启动服务可执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-local.ps1 -CheckOnly
```

[启动脚本](../scripts/start-local.ps1)使用当前环境变量；密码未设置时在本机提示输入。它只读核对数据库连接和表结构，不自动执行迁移。检查成功会将应用密钥通过Windows DPAPI加密，保存到`.local/startup-secrets.json`；数据库密码不会保存在该文件中。

后续启动应沿用该文件和原Windows账户。数据库已有加密私钥、但本机没有主密钥时，脚本要求输入原`KEY_ENCRYPTION_KEY`；只有确认库中没有加密私钥时才会生成新主密钥。`-SettingsPath`可指定其他本机配置文件，`-JarPath`可指定其他后端JAR。`-CheckOnly`成功时也会保存本机密钥配置。

DPAPI文件绑定本机Windows账户，不能直接作为跨机器备份。迁移部署需要另行安全保留原应用密钥。已有明文签名私钥可通过“个人身份与密钥”页面迁移为密文。

也可在配置好上述环境变量后直接运行：

```powershell
java -jar target/parts-trace-backend-1.0-SNAPSHOT.jar
```

直接运行JAR不会替你生成密钥或执行启动脚本的表结构预检查。

## 4. 登录与联调

初始化脚本中的管理员为`admin`，初始密码为`admin123`；已有数据库修改过密码时，以实际密码为准。新建库中的账户与角色以初始化脚本为准，管理员应在交付使用前修改默认密码。

前端按[前端README](../../parts-trace-frontend/README.md)启动，默认地址为`http://localhost:5173`。开发请求通过`/api`代理到`http://localhost:8080`。接口文档地址为`http://localhost:8080/swagger-ui.html`。

普通`mvn package`不负责构建前端。源码开发分别启动后端与Vite；同端口页面需要先构建前端、使用`windows-package`配置将`dist`嵌入JAR，并启用桌面页面路由。Windows启动器已包含这些运行参数，具体见[部署说明](部署说明.md)。独立版默认端口为18080，与源码后端的8080分别配置。

## 5. 常见错误

| 错误 | 核对方式 |
| --- | --- |
| `Access denied ... using password: NO` | 在启动终端设置实际`KEWEI_DBPWD`，或通过脚本输入密码 |
| `Table ... revoked_token doesn't exist` | 按第2节执行增量升级，并运行结构检查 |
| `JWT_SECRET`长度不足 | 使用至少32字符的随机密钥；已有环境沿用原密钥 |
| 私钥无法解密 | 核对原`KEY_ENCRYPTION_KEY`及Windows账户，不用新主密钥替代旧值 |
| 前端页面可打开但请求失败 | 检查后端8080端口、数据库和前端代理配置 |
| 真实链连接或合约身份不匹配 | 按[双平台接入说明](双平台接入说明.md)核对各逻辑链配置 |

运行日志为`logs/parts-trace.log`。测试步骤和既有验证记录集中在[测试说明](测试说明.md)。
