# 部署说明

本文中的命令和路径相对于`parts-trace-backend/`。数据库准备和本地启动统一按[运行说明](运行说明.md)执行；真实链参数统一按[双平台接入说明](双平台接入说明.md)配置。

## 1. 组件与端口

| 组件 | 默认配置 | 文件依据 |
| --- | --- | --- |
| 后端 | Java 8或Java 11，端口8080 | `pom.xml`、`src/main/resources/application.yml` |
| 数据库 | MySQL 8，库名`parts_trace`，端口3306 | `src/main/resources/application.yml` |
| 前端开发服务 | 端口5173，`/api`代理至后端8080 | 前端`vite.config.js` |
| 对象存储 | 默认数据库对象存储；IPFS API端口5001 | `src/main/resources/application.yml` |
| 链服务 | 默认模拟账本；真实模式逐链选择SDK | `blockchain.networks`配置 |

前端开发端口不等于正式部署端口。正式环境由Web服务提供静态文件并转发API。

## 2. 构建与部署

后端构建命令为`mvn package`，产物为`target/parts-trace-backend-1.0-SNAPSHOT.jar`。启动前完成数据库升级并设置数据库连接、`JWT_SECRET`和`KEY_ENCRYPTION_KEY`。正式服务使用稳定的外部密钥配置；本地Windows脚本的DPAPI文件不直接复制到其他机器使用。

前端在`parts-trace-frontend/`内执行`npm ci`、`npm run build`，产物为该目录下的`dist/`。Web服务需要：

1. 通过静态目录提供`dist/`。
2. 将`/api`请求转发到后端，并保留`/api`前缀。
3. 对前端页面路由返回`index.html`，使刷新页面时仍能进入Vue应用。

默认前端接口基址为`/api`。若修改`VITE_API_BASE_URL`，需重新构建前端；该变量不会修改后端监听端口，也不会自动修改Vite的代理目标。

`npm run preview`用于检查构建结果。本项目锁定的Vite 4会在未单独设置`preview.proxy`时沿用`server.proxy`，因此当前预览服务也可将`/api`转发到8080。静态文件部署到其他Web服务后，需要由该Web服务提供API转发，不能依赖Vite配置生效。

## 3. 存储模式

| 链模式 | 对象模式 | 使用范围 |
| --- | --- | --- |
| `db` | `db` | 本地功能验证；核验结果明确标记模拟账本 |
| `real` | `db` | 使用真实链，原文仍保存在数据库对象存储 |
| `real` | `ipfs` | 使用真实链与实际IPFS服务 |

`chainmaker`仅作为`real`的兼容旧值，不代表全部逻辑链强制使用长安链。真实模式包含两种SDK驱动，不需要旧的SDK启用开关。调用失败保留任务错误和重试状态，不创建模拟成功交易。

IPFS模式使用`IPFS_HOST`、`IPFS_PORT`连接Kubo。原文可读性与链上确认分别检查；数据库对象存储的功能测试结果不能作为实际IPFS结果。

## 4. 部署后核对

依次验证登录、单件DID和物理标识、生产记录、质检结果、物流记录、凭证核验与撤销、异常冻结与复检解冻。真实链环境还需核对源链存证、主链中继回执、故障后的任务重试和原文读取。

保留实际交易哈希、确认区块高度、请求时间和错误记录。当前项目的已验证范围见[测试说明](测试说明.md)，本地EVM执行结果不能替代FISCO节点联调结果。
