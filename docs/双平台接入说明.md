# 长安链与FISCO BCOS双平台接入说明

本文路径和命令均相对于`parts-trace-backend/`，单独标注子目录的命令除外。配置依据为[application.yml](../src/main/resources/application.yml)和[ChainNetworkProperties](../src/main/java/com/kewei/parts/infrastructure/chain/ChainNetworkProperties.java)。

## 1. 平台与逻辑链

项目使用长安链Java SDK 2.3.3及FISCO BCOS Java SDK 3.8.0。FISCO适配面向3.x的EVM群组，不能直接使用2.x配置或WASM群组。

| 逻辑链编码 | 默认平台 | 业务用途 |
| --- | --- | --- |
| `main-regulator` | `CHAINMAKER` | 监管汇聚、凭证登记和撤销 |
| `sub-production` | `CHAINMAKER` | 生产记录及单件DID文档存证 |
| `sub-quality` | `CHAINMAKER` | 质检记录存证 |
| `sub-logistics` | `FISCO_BCOS` | 物流记录存证 |

每条逻辑链均可独立选择上述平台。存证写入与读取、凭证登记与撤销、源链核对及主链中继接收均按配置路由。主监管链也可改为FISCO；应用的汇聚目标仍是`main-regulator`。

`PARTS_TRACE_CHAIN_MODE=real`启用真实SDK，旧值`chainmaker`行为相同。`db`不初始化真实SDK。旧的`CHAINMAKER_SDK_INVOKE_ENABLED`不再作为启动开关。

真实模式检查实际链ID、FISCO群组和固定账户、重复账本绑定，以及合约`contract_info`返回的版本和逻辑链编码。合约格式须为`parts-trace-anchor/v2`。同一FISCO物理链的不同群组可作为不同账本；同一群组的不同合约地址不能冒充多个独立账本。

## 2. 逐链配置

| 逻辑链 | 环境变量前缀 |
| --- | --- |
| `main-regulator` | `MAIN_CHAIN_` |
| `sub-production` | `PRODUCTION_CHAIN_` |
| `sub-quality` | `QUALITY_CHAIN_` |
| `sub-logistics` | `LOGISTICS_CHAIN_` |

每组前缀均提供以下后缀。例如，物流SDK配置变量为`LOGISTICS_CHAIN_CONFIG`。

| 后缀 | 内容 |
| --- | --- |
| `PLATFORM` | `CHAINMAKER`或`FISCO_BCOS` |
| `CONFIG` | 外部SDK配置的Spring资源地址，如`file:/deploy/logistics/sdk_config.toml` |
| `ID` | 预期物理链ID，建议显式填写以核对部署 |
| `GROUP` | FISCO群组，默认`group0` |
| `CONTRACT_ADDRESS` | FISCO已部署合约地址，`0x`后接40位十六进制字符 |
| `ACCOUNT` | FISCO固定交易账户地址，应与SDK加载的账户一致 |

长安链合约名通过`CHAINMAKER_CONTRACT_NAME`统一设置，默认`trace_anchor`；也可在外部Spring配置的`blockchain.networks.<逻辑链>.contract-name`逐链覆盖。真实模式还需配置`RELAY_PRIVATE_KEY`，内容为PKCS8 RSA私钥DER的Base64编码。

以下为物流子链配置示例；路径、链ID和地址必须替换为实际值：

```text
PARTS_TRACE_CHAIN_MODE=real
LOGISTICS_CHAIN_PLATFORM=FISCO_BCOS
LOGISTICS_CHAIN_CONFIG=file:/deploy/logistics/sdk_config.toml
LOGISTICS_CHAIN_ID=chain0
LOGISTICS_CHAIN_GROUP=group0
LOGISTICS_CHAIN_CONTRACT_ADDRESS=实际已部署合约地址
LOGISTICS_CHAIN_ACCOUNT=实际固定交易账户地址
```

真实模式需要同时配置其余逻辑链。旧变量`CHAINMAKER_MAIN_CONFIG`、`CHAINMAKER_PRODUCTION_CONFIG`、`CHAINMAKER_QUALITY_CONFIG`及`FISCO_LOGISTICS_CONFIG`仍作为对应新变量未设置时的默认值；`FISCO_LOGISTICS_CHAIN_ID/GROUP/CONTRACT_ADDRESS/ACCOUNT`也保留兼容。

`BLOCKCHAIN_TIMEOUT_MS`用于长安链调用，默认60000毫秒。FISCO原生消息超时在TOML的`network.messageTimeout`配置，样例同为60000毫秒。DID中原有的`chainmaker`方法名不决定SDK选择。

## 3. 长安链接入

SDK模板为[src/main/resources/chainmaker/sdk_config.yml.example](../src/main/resources/chainmaker/sdk_config.yml.example)。分别填写实际链ID、组织、节点、TLS主机名、CA、TLS身份和交易签名身份，证书与私钥文件建议使用绝对路径。

合约源码为`contracts/trace_anchor/`，使用DockerGo运行时。各链部署包含`contract_info`的当前版本，并以`local_chain_code`设置对应逻辑链编码；接收中继的主链还需登记各源链的受信中继公钥。构建和初始化参数见[合约说明](../contracts/README.md)。

应用会在内存中将软件PEM私钥规范为PKCS8，以保留SEC1普通EC和SM2曲线参数，不改写原私钥文件。旧合约状态不会自动迁入新版本。

## 4. FISCO配置与部署

SDK样例为[src/main/resources/fisco/sdk_config.toml.example](../src/main/resources/fisco/sdk_config.toml.example)。复制到部署目录，填写节点地址、证书目录和固定交易账户的`accountFilePath`。`expected-account`必须等于该PEM账户地址；不能依赖每次启动生成的随机账户。

FISCO使用`contracts/fisco/TraceAnchor.sol`和`RsaSha256.sol`。普通版ABI和字节码位于`src/main/resources/fisco/`，并随JAR提供。部署清单样例为[contracts/fisco/deploy.example.json](../contracts/fisco/deploy.example.json)。

填写清单中的SDK资源地址、群组、预期物理链ID、固定账户、逻辑链编码、写入账户及受信源链公钥。清单只放公钥及外部配置引用，不放私钥。然后从后端目录执行检查：

```powershell
java '-Dloader.main=com.kewei.parts.infrastructure.fisco.FiscoContractDeployer' -cp target/parts-trace-backend-1.0-SNAPSHOT.jar org.springframework.boot.loader.PropertiesLauncher /deploy/logistics/deploy.json
```

`/deploy/logistics/deploy.json`是示例部署路径。Windows可替换为部署清单的实际本地路径。默认只检查连接、参数和字节码，不发送交易；增加末尾参数`--deploy`才部署。成功时核对真实回执和新合约身份，输出地址、交易哈希及区块高度，再将地址写入该链的`CONTRACT_ADDRESS`配置。

部署账户为合约所有者；业务使用其他账户时，应在清单`writerAddresses`或合约`set_writer`中授权。主链接收中继时，`relayPublicKeys`应按源链编码登记X.509 DER RSA公钥的Base64；只提供源存证的物流子链可使用空映射。

SDK依赖本机JNI动态库，首次加载需要能写入运行账户的用户目录缓存。证书、固定账户、群组和JNI初始化失败均会明确报错。

## 5. 跨链信任与密码要求

应用先读取源链锚点，核对摘要、DID和CID，再签署源链编码、源交易、源高度、业务类型与编号、主体、摘要、CID、目标链和时间。目标合约检查写入权限、受信公钥、RSA-SHA256签名、目标链、时效和重复消息。

两种平台共用同一签名原文：字段名按字典序排列，逐行使用`名称=值`并以换行结束，以UTF-8编码签名。消息有效期为目标链时间之前300秒至之后60秒。同一源交易的相同内容可重试，不同内容即使重新签名也不能覆盖。

当前应用使用一把中继私钥；主链可以为多个源链登记同一对应公钥。跨平台互操作使用2048至4096位、指数65537的RSA密钥，位数取8的倍数。该机制依赖授权中继，不独立验证源链共识或交易包含证明。

## 6. 国密群组与验证范围

国密群组需要相应证书、账户和官方0.8.11国密编译器。在`contracts/fisco/`将`SOLC_GM`设为编译器绝对路径，执行`npm run compile:sm`。脚本核对SM3函数选择器后生成`src/main/resources/fisco/TraceAnchor.sm.bin`。

部署清单通过`smBinary`指定该文件的资源地址。工具按实际密码类型选择字节码；缺少国密字节码时明确失败。当前交付只包含已验证的普通EVM字节码，国密编译输出和国密节点尚未实测。

两种平台的本地验证和外部节点联调范围统一见[测试说明](测试说明.md)。
