# 功能与数据说明

本文以当前后端实体、控制器和前端路由为依据。源码路径相对于`parts-trace-backend/`；所有接口地址包含`/api`前缀。完整接口参数以运行后的`/swagger-ui.html`及控制器定义为准。

## 1. 当前业务范围

应用提供账号与角色管理、个人DID与密钥、零部件主数据与单件、物理标识绑定、生产/质检/物流事件、可验证凭证、质量异常处置、追溯查询、文件导出和跨链记录展示。

当前事件类型为`production`、`quality`、`logistics`。早期材料中的装配、链上任意规则执行、选择性披露和源链轻客户端证明，不作为当前已实现功能描述。

## 2. 主数据、单件与DID

| 对象 | 数据表 | 主要关系 |
| --- | --- | --- |
| 零部件主数据 | `parts_info` | 一条批次物料记录，包含编码、名称、批次和数量 |
| 物理单件 | `parts_unit` | 通过`parts_id`归属主数据，以`unit_id`区分具体实物 |
| 零部件DID | `parts_did` | 关联`parts_id`与`unit_id`，保存文档、物理绑定及生命周期状态 |
| 业务事件 | `trace_event`及对应明细表 | 关联单件、DID、业务阶段、操作人及前序事件 |
| 凭证 | `verifiable_credential` | 关联签发者、主体、事件和单件，保存签名及存证元数据 |

一条数量为3的`parts_info`可以展开为3个`parts_unit`。主数据列表的一行、展开后的三个单件，以及工作台中的主数据下拉，是不同层次的记录。`partsId`不能替代`unitId`表示某个具体实物。

批次操作可通过`partsIds`限定主数据，通过`unitIds`限定单件；具体范围以提交的请求及服务端校验为准。单件综合凭证使用`unitId`明确选择主体，避免将同批次其他单件的经历混入。

零部件DID的物理绑定类型为`QRCODE`或`RFID`。`didStatus`为0未激活、1已激活、2已冻结、3已归档；`bindStatus`单独表示是否绑定物理标识。二者不能混为“已上链”。链是否确认还需查看存证状态与回执。

## 3. 业务流程与权限

1. 管理员配置用户、角色及所属机构；业务账号在个人页面绑定DID并管理密钥。
2. 生产账号创建主数据和单件，为单件生成DID并绑定物理标识。
3. 按生产、质检、物流阶段登记事件并关联凭证；身份和机构取自服务端登录信息。
4. 不合格质检产生关联告警并冻结相应主数据下的同批次单件。冻结期间禁止物流流转，允许合格复检；关闭关联告警后再授权解冻。
5. 查询时核对DID文档、事件、凭证、对象原文和链上摘要。凭证撤销后，各核验入口均报告无效。

服务端按账户状态、用户类型及启用角色检查权限，相关代码为`CurrentActor`、认证/权限拦截器、控制器与业务服务。生产、质检、物流写入分别要求相应角色或管理权限；密钥与个人资料操作还检查本人归属。隐藏前端菜单不能代替服务端授权。

## 5. 存证、凭证与状态

真实模式在业务事务中保存任务，提交后由后台执行SDK调用；模拟模式明确返回模拟标记。业务/中继状态0表示待处理，1表示真实链确认，2表示模拟，3表示处理中，-1表示失败。未确认时不使用随机交易编号冒充回执。失败任务保留错误原因、重试次数及下次重试时间，最多自动尝试10次。

启用[多机构核验](多机构核验说明.md)时，跨链总览额外返回`confirmation`配置摘要，各记录带有核验状态和有效签名人数。确认凭据保存在`relay_confirmation`，接口不返回凭据原文；`CONFIRMED`表示已核验待上链，`COMMITTED`表示主链已确认。该功能默认关闭，与原业务状态分别展示。

凭证签名使用项目内部v2封装，覆盖凭证编号、类型、签发者、主体、单件、关联事件、时间和业务内容，对对象键排序并以UTF-8进行RSA-SHA256签名。私钥采用服务端AES-GCM加密托管；当前实现不属于用户端独占私钥或选择性披露方案。

核验检查签发资格、签名、有效期、撤销、单件归属、DID文档、关联事件、原文与链上摘要。原文不可读或链不可用时不会默认通过。已存证记录作废后保留历史，不物理删除其存证事实。

自定义规则仅执行已支持的质量JSON条件和`alert`、`freeze_batch`动作，不执行任意SQL。条件包括`inspectionResult`的`eq`及`unqualifiedQuantity`的`eq/gt/gte/lt/lte`；旧的时间、温度等文字规则不作为已接入能力展示。
