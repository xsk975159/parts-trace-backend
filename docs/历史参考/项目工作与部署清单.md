# 项目工作与部署清单

> 历史设计参考：正文保留当时的需求、模型、命令和接口方案，不代表当前源码。源码路径沿用当时后端目录约定；实际使用以[当前文档](../README.md)为准。

本文汇总 **已在代码仓完成的开发**、**不依赖链即可验证项**，以及 **必须在长安链/运维环境就绪后才能做的事**，便于论文交付与联调节奏对齐。

---

## 一、不依赖链环境已完成的开发（代码层）

| 类别 | 内容 | 说明 |
|------|------|------|
| 合约源码 | `contracts/trace_anchor/main.go` | `save_anchor`、`append_vc`、`revoke_vc`、`receive_cross_anchor` |
| 锚定请求模型 | `ChainAnchorRequest` | `businessType`、`businessId`、`dataHash`，可选 `objectCid`、`partsDid` |
| 存储适配 | `ChainStorageAdapter.storeAnchor` | `storeHash` 默认转最小字段 `storeAnchor` |
| DB 模拟链 | `DbChainStorageAdapter` | `storeAnchor`；`appendVcIfSupported` 写入 `blockchain_record`（`businessType=vc_append`） |
| 长安链适配 | `ChainMakerChainStorageAdapter` | SDK 就绪则 invoke；否则日志 + **DB 镜像**，业务可继续 |
| SDK 封装 | `ChainMakerSdkInvoker` | `@ConditionalOnProperty` `chainmaker.sdk.invoke-enabled=true`；`invokeSaveAnchor`、`invokeAppendVc`、`invokeReceiveCrossAnchor` |
| 跨链封装 | `CrossChainRelayService` | 主链 `receive_cross_anchor`；SDK 未就绪时仅 debug |
| 业务挂接 | `TraceEventServiceImpl`、`PartsServiceImpl`、`VerifiableCredentialServiceImpl` | 事件 / DID 文档 / VC 持久化时 `storeAnchor`；VC 后接 `appendVcIfSupported` |
| 构建 | `mvn -DskipTests compile` | 已含 `protobuf-java` 等与 SDK 兼容依赖；本地可编译通过 |
| 文档 | `docs/*.md`（中文名为主） | 索引见 [README.md](../README.md) |

## 二、本地即可完成的验证（无需真实链节点）

| 验证项 | 做法 |
|--------|------|
| 后端编译 | `cd parts-trace-backend && mvn -DskipTests package` |
| 默认演示模式 | `PARTS_TRACE_CHAIN_MODE=db`、`PARTS_TRACE_OBJECT_MODE=db`，起服务跑通 DID / 事件 / VC API |
| 链模式 + 不发交易 | `PARTS_TRACE_CHAIN_MODE=chainmaker`、`CHAINMAKER_SDK_INVOKE_ENABLED=false`，确认仍有 `blockchain_record` 镜像且无启动报错（需合法占位 `sdk_config.yml` 时，以你环境为准；若仅 db 模式可跳过） |
| 前端 | `parts-trace-frontend` 指向后端，跑通工作台与溯源页面（与具体环境相关） |

## 三、必须在长安链 / 运维环境就绪后完成的工作

以下步骤依赖 **真实链、证书、已部署 Wasm**，无法在纯单机代码仓内「替用户完成」：

| 序号 | 工作项 | 说明 |
|------|--------|------|
| 1 | 准备网络与证书 | 按联盟链文档准备节点；填写 `sdk_config.yml`（私钥勿提交 Git） |
| 2 | 编译与部署合约 | `contracts/trace_anchor` → WASM；`contract create` / 升级；合约名与 `chainmaker.wasm-contract-name` 一致 |
| 3 | 打开真实 invoke | `PARTS_TRACE_CHAIN_MODE=chainmaker`、`CHAINMAKER_SDK_INVOKE_ENABLED=true` |
| 4 | 端到端联调 | 创建 DID / 事件 / VC，核对链上交易与 `blockchain_record` 中 txId、块高 |
| 5 | IPFS（若论文要求链下全文） | 部署 Kubo，`PARTS_TRACE_OBJECT_MODE=ipfs`，核对 CID 与 `object_cid` 参数 |
| 6 | 跨链（5.2） | 第二套链或 second chain-id；中继监听从链 → 调 `CrossChainRelayService` / 主链 `receive_cross_anchor`；后续可加 SPV/默克尔 |
