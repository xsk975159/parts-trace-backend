# 溯源工作台落地与交接说明

## 实施范围

本次交互改造采用记录驱动主入口，新增前端工作台页面并补后端组合接口，不破坏既有细粒度接口。
当前职责边界：`记录中心` 是唯一执行入口；`批次流程` 仅承担只读监控与异常定位。

## 阶段划分

### Phase 1（已落地）

- 前端新增 `溯源工作台`，包含：
  - 批次流程（只读监控，不含执行按钮）
  - 记录中心（统一表单+动态字段，唯一执行入口）
  - 链上凭证入口
  - 链条与报告入口
- 批次流程支持一键跳转记录中心并自动带入当前批次上下文
- 记录中心支持内联 DID 快操作：
  - 生成 DID
  - 查看 DID 文档
  - 校验 DID
- 记录后状态反馈统一为三段：
  - 事件存证
  - VC 签发
  - 链条更新
- 后端新增组合编排接口：
  - `POST /api/trace/workbench/batch-action`（记录中心调用，批量处理单件）
  - `GET /api/trace/workbench/batches`
  - `GET /api/trace/workbench/batch-overview`
  - `GET /api/trace/workbench/batch-units`

### Phase 2（建议下一步）

- 任务看板细化为可领取、可流转、可 SLA 监控
- 组合接口增加失败补偿与重试状态
- 批量工作流（批量记录、批量签发）从工具接口升级为作业化任务

### Phase 3（迁移阶段）

- 将 `ChainStorageAdapter` 替换为长安链真实实现
- 将 `ObjectStorageAdapter` 替换为 IPFS 真实实现
- 保持工作台交互与业务接口不变，避免培训和切换成本

## 验收口径

- 同一动作（生产/质检/物流）在工作台中仅有一个可执行入口（记录中心）
- 批次流程只展示进度与明细，不出现执行型按钮
- 用户从“选择批次”到“事件+VC+链条更新”，不超过 1 个主页面
- 关键动作均有可见状态反馈，失败能定位到阶段
