# 前后端部署说明

本文命令和路径相对于 `parts-trace-backend/`，明确进入前端目录的步骤除外。数据库准备、账号与应用密钥按[运行说明](运行说明.md)处理，真实链参数按[双平台接入说明](双平台接入说明.md)配置。

## 1. 运行方式与端口

| 方式或组件 | 默认端口 | 说明 |
| --- | --- | --- |
| 源码后端、Windows普通版 | 8080 | 后端配置为 `server.port`，可由 `SERVER_PORT` 覆盖 |
| Vite开发页面 | 5173 | `/api` 代理至后端8080，端口占用时以终端输出为准 |
| Vite本地预览 | 4173 | 检查 `dist/`，仍需可用的后端 |
| Windows独立版 | 18080 | 页面和API共用端口，由运行包 `config/runtime.json` 配置 |
| 外部MySQL | 3306 | 库名 `parts_trace`，按实际部署修改 |
| 独立版私有MySQL | 首次从13306至13336选择 | 只监听127.0.0.1，后续沿用所选端口 |
| 配套长安链RPC | 12301 | Docker网络只向127.0.0.1开放 |
| 配套FISCO RPC | 20200 | Docker网络只向127.0.0.1开放 |
| IPFS API | 5001 | 启用 `ipfs` 模式时连接自行部署的Kubo |

后端和运行包的端口分别配置。Vite代理不会自动跟随后端改端口；修改目标后需要重启前端服务。

## 2. 源码开发

后端执行 `mvn package` 后，按[运行说明](运行说明.md)启动。前端在 `parts-trace-frontend/` 内执行 `npm ci`、`npm run dev`；两者在各自终端运行。后端数据库及密钥应预先准备，源码启动不会自动初始化数据库。

## 3. 静态页面独立部署

前端执行 `npm ci`、`npm run build`，产物为前端目录的 `dist/`。Nginx等Web服务需完成以下配置：

1. 通过静态目录提供 `dist/`。
2. 将 `/api` 转发到后端，并保留 `/api` 前缀。
3. 将前端业务页面路由回退到 `index.html`，使刷新页面仍可进入Vue应用。

默认接口基址为 `/api`。`VITE_API_BASE_URL` 在前端启动或构建时读取，修改后重新构建；它不修改后端端口或Vite代理。

`npm run preview` 用于本地检查构建结果。当前锁定的Vite 4.5.14在未设置 `preview.proxy` 时沿用 `server.proxy`，预览联调仍需启动后端。部署到其他Web服务后，由该服务独立配置API转发。

## 4. 页面与后端同端口部署

先在前端目录执行 `npm ci`、`npm run build`，再在后端目录执行：

```powershell
mvn -Pwindows-package package
```

该配置将前端 `dist/` 写入后端JAR的 `static/`，并包含桌面启动所需的数据库检查资源。前端与后端共用端口，不再需要Vite。

Windows运行包由启动器传入 `--parts.trace.desktop.enabled=true`，启用业务页面的路由回退。自行运行包含页面的JAR时，也需启用该参数，并自行提供数据库和密钥配置：

```powershell
java -jar target/parts-trace-backend-1.0-SNAPSHOT.jar --parts.trace.desktop.enabled=true
```

普通 `mvn package` 不执行前端构建，也不保证包含静态页面。EXE运行包由[Windows打包脚本](../scripts/package-windows.ps1)完成前端构建、JAR打包和启动器编译。已制作的版本见[交付目录](../../output/README.md)。

## 5. 链与对象存储

| 链模式 | 对象模式 | 用途 |
| --- | --- | --- |
| `db` | `db` | 本地业务验证，账本结果明确标记为模拟 |
| `real` | `db` | 使用真实链，业务原文保存在数据库对象存储 |
| `real` | `ipfs` | 使用真实链和实际IPFS服务 |

链模式通过 `PARTS_TRACE_CHAIN_MODE` 设置，对象模式通过 `PARTS_TRACE_OBJECT_MODE` 设置。`chainmaker` 仅作为 `real` 的兼容旧值。真实模式逐链选择长安链或FISCO SDK；调用失败保留错误及重试状态，不生成模拟成功回执。

配套[Docker环境](../deploy/heterogeneous/README.md)提供长安链2.3.10、FISCO BCOS 3.16.3、合约自动部署和实链验收，再将SDK与合约配置接入独立版。网络采用授权中继签名，多机构联合核验需按[专门说明](多机构核验说明.md)另行配置。

IPFS模式通过 `IPFS_HOST` 和 `IPFS_PORT` 连接Kubo。原文读取和链上确认分别检查，数据库对象存储的结果不作为实际IPFS测试结果。

## 6. 部署后核对

按顺序检查登录、单件DID与物理标识、生产记录、质检、物流、凭证核验和撤销、异常冻结及复检解冻。真实链环境另核对源链存证、监管主链中继回执、任务失败重试及原文读取。

保留交易哈希、确认区块高度和错误记录。已完成的本地测试、单机实链验证与尚未验证的范围见[测试说明](测试说明.md)。已有数据库升级前备份，既有加密私钥继续使用原主密钥；Windows DPAPI密钥文件绑定原账户，迁移部署时单独安排密钥与数据迁移。
