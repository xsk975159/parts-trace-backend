# 测试与验证说明

本文命令和路径相对于`parts-trace-backend/`，明确进入合约目录的命令除外。测试源码和夹具是正式项目文件，编译结果、运行日志及临时数据库不属于源码。

## 1. 自动化测试

| 范围 | 位置 | 执行方式 |
| --- | --- | --- |
| 后端 | `src/test/java/` | 后端目录执行`mvn test` |
| 长安链Go合约 | `contracts/trace_anchor/main_test.go` | 进入该目录执行`go test ./...` |
| Solidity合约 | `contracts/fisco/test/` | 先运行后端测试，再进入该目录执行`npm ci --ignore-scripts`和`npm test` |

后端测试生成`target/fisco-codec-vectors.json`，供本地EVM执行真实FISCO Java SDK编码的部署和调用数据。缺少该文件时，单独运行Solidity测试会跳过相应用例，不能将跳过记为通过。

Go和Solidity均使用`contracts/trace_anchor/testdata/relay-vector.json`中的Java签名向量；该文件只有测试公钥、参数和签名，不包含私钥。FISCO原生SDK测试需要能加载JNI动态库并访问其本机缓存。

## 2. HTTP集成验证

[integration_smoke.py](../scripts/integration_smoke.py)只连接`http://127.0.0.1:18080`，且要求显式设置`CCF_RUN_ISOLATED_INTEGRATION=1`。测试会创建业务记录、撤销凭证、禁用测试查看员并注销管理员令牌，应使用专门的测试实例。

独立MySQL实例要求：端口`13316`，项目根目录下的数据目录`tmp/integration/mysql-isolated/`，库名`parts_trace`。这是后端目录的`../tmp/integration/mysql-isolated/`。该实例需要单独初始化，不能与3306业务实例共用数据目录。

仅在独立实例中导入新库初始化脚本，创建只访问测试库的`ccf_test@127.0.0.1`空密码账户。`PrepareIntegrationFixtures.java`使用这一固定连接，并核对实际端口与数据目录后才更新样例账户密码和状态。

在专用测试终端设置`CCF_TEST_PASSWORD`为至少12字符的测试密码，设置显式启用变量；使用Java 11源码启动方式准备夹具：

```powershell
$env:CCF_RUN_ISOLATED_INTEGRATION = '1'
# CCF_TEST_PASSWORD需在本终端预先设置。
mvn dependency:build-classpath '-Dmdep.outputFile=target/test-classpath.txt'
$testClasspath = (Get-Content target/test-classpath.txt -Raw).Trim()
java -cp $testClasspath scripts/PrepareIntegrationFixtures.java
```

另开专用测试服务终端，连接上述13316实例，端口设为18080，链和对象存储均设为`db`，并配置该测试环境独立的JWT密钥和私钥加密主密钥。不要更换业务环境原密钥来运行测试。

在准备夹具的终端执行：

```powershell
$env:CCF_TEST_BASE_URL = 'http://127.0.0.1:18080'
python scripts/integration_smoke.py
```

结果写入`target/test-results/integration-results.json`。再次运行前应重新准备测试账户；已有加密测试私钥也需要沿用相应测试主密钥，或在独立实例中重新初始化测试库。
